AI Cost Glossary

40+ definitions for AI and LLM terminology — from tokens and context windows to RAG, fine-tuning, and advanced pricing concepts. Search in real-time below.

A

Agent

An AI system that autonomously plans and executes multi-step tasks using tools, memory, and decision loops. Agents call LLMs repeatedly, use tool results to inform next steps, and can browse the web, write code, or query databases.

Example: An agent given "research competitors and write a report" might search the web, extract data, compare it, and draft a document — all without human input.

API (Application Programming Interface)

A standardized interface for accessing AI model capabilities over the internet. AI APIs accept HTTP requests containing your prompt and return generated text. Most providers use a REST API with JSON payloads.

Example: POST https://api.openai.com/v1/chat/completions with your messages and model name returns a JSON response with the AI's reply.
fundamentals

Assistant Message

In the chat/messages API format, this is the AI model's previous response that you include in conversation history. Assistant messages are counted as input tokens in subsequent requests, so long assistant replies increase costs over multi-turn conversations.

Example: Including the model's previous 500-word reply in the next request adds ~667 input tokens to that request's cost.
pricingconversation
B

Batch API

An asynchronous API endpoint that processes requests in bulk at a lower cost, typically with a 24-hour completion SLA. OpenAI and Anthropic offer 50% discounts for batch processing compared to real-time inference.

Example: Submitting 10,000 document classification requests to OpenAI's Batch API costs 50% less than real-time requests and completes within 24 hours.
cost optimizationpricing
C

Cache Hit / KV Cache / Prefix Caching

When a provider has already computed the attention keys and values for an identical prefix (e.g., your system prompt), subsequent requests with that same prefix can reuse those cached computations. Cache hits significantly reduce latency and cost — Anthropic and OpenAI charge as little as 10% of normal price for cached tokens.

Example: A 2,000-token system prompt that's identical across 1,000 requests costs full price once, then ~90% less for the cached portion in subsequent requests.
cost optimizationperformance

Completion Tokens / Output Tokens

The tokens generated by the AI model in its response. Completion tokens are billed separately from input tokens, typically at a 3–5× higher rate because each token requires a full model forward pass. Minimizing unnecessary verbosity in outputs directly reduces costs.

Example: Asking a model to "respond in JSON with just the sentiment label" instead of "explain the sentiment" can reduce output tokens by 90%.
pricingfundamentals

Context Window / Context Length

The maximum number of tokens a model can process in a single API call (input + output combined). Larger context windows allow longer documents and conversations but have upper token limits. Common sizes: 32K, 128K (most models), 200K (Anthropic), 1M (Google Gemini).

Example: A model with a 128K context window can process approximately 100,000 words in a single request — roughly the length of a full novel.
fundamentalslimits

Cost Per Request / Cost Per Million Tokens

Two common ways to express AI pricing. Cost per million tokens ($/M) is the standard provider metric. Cost per request is calculated by multiplying your average token counts by the per-million rates and dividing by 1,000,000. Most cost planning should work in $/M tokens, then convert to $/request for your use case.

Example: GPT-4o at $2.50/M input, 1,000 input tokens per request = $0.0025 per request in input costs alone.
pricingfundamentals
E

Embedding / Vector

A numerical representation of text as a fixed-size list of floating-point numbers (a vector). Embeddings capture semantic meaning, allowing similarity search across large text collections. Embedding model APIs are much cheaper than generation APIs — typically $0.02–$0.13/M tokens.

Example: "The cat sat on the mat" and "A feline rested on a rug" will have very similar embedding vectors despite using different words.
ragpricing
F

Few-Shot Learning

Providing a small number of input/output examples in the prompt to demonstrate the desired behavior. Few-shot prompting improves accuracy but adds tokens (cost). Typically 2–5 examples are sufficient; more examples rarely improve results proportionally.

Example: Showing 3 example sentiment classifications before asking the model to classify new text improves accuracy for specialized domains.
promptingcost impact

Fine-Tuning / RLHF / LoRA

Fine-tuning adapts a pretrained model to a specific task using custom training data. RLHF (Reinforcement Learning from Human Feedback) trains models to follow instructions using human preference data. LoRA (Low-Rank Adaptation) is an efficient fine-tuning technique that updates only a small fraction of model weights, reducing training cost significantly.

Example: Fine-tuning GPT-4o Mini on your customer support conversations can match GPT-4o quality for your specific domain at a fraction of the inference cost.
trainingcost optimization

Foundation Model

A large AI model pretrained on massive datasets that serves as the base for many downstream applications. Foundation models (GPT-4, Claude, Gemini) are expensive to train but cheap to use via API. The term emphasizes that these models are "foundations" upon which other capabilities are built.

Example: GPT-4o is a foundation model that can be used directly or fine-tuned to create specialized models for medical, legal, or coding applications.
fundamentals

Frequency Penalty / Presence Penalty

Sampling parameters that reduce repetition in model outputs. Frequency penalty discourages repeating tokens proportional to how often they've appeared. Presence penalty adds a flat penalty for any token that has appeared at all. Neither directly affects cost, but reducing repetition can shorten outputs and lower costs indirectly.

Example: Setting frequency_penalty=0.5 helps prevent the model from repeating the same phrases in a long generated document.
parameters

Function Calling / Tool Use

An API feature allowing models to call predefined functions and use external tools. Function/tool definitions are included in the request as additional input tokens. A large set of tool definitions can add hundreds of tokens per request. The model's function call response is counted as output tokens, and the function result fed back is input tokens.

Example: Defining 10 tools with 100 tokens each adds 1,000 input tokens to every request in your tool-using agent — at GPT-4o rates, an extra $0.0025 per request.
featurespricing impact
G

Grounding / Citation / Hallucination

Grounding connects model responses to verified sources (documents, search results). Citation means providing references for claims. Hallucination is when a model generates plausible-sounding but incorrect information. Grounding via RAG increases token costs but reduces errors, which can be cheaper than the cost of incorrect outputs.

Example: A grounded medical Q&A system passes retrieved PubMed abstracts as context, adding 2,000 input tokens per query but ensuring medically accurate responses.
qualityrag
H

Hallucination

When a language model generates text that is factually incorrect, invented, or not supported by its training data or provided context. Hallucinations are more common in smaller models and without grounding. The cost of hallucinations (human review, errors) often exceeds the cost savings of using cheaper models.

Example: A model confidently citing a scientific paper with the wrong authors and journal, even though no such paper was provided in the context.
qualityrisks
I

Inference / Training / Deployment

Inference is running a trained model to generate outputs (what you pay for with API calls). Training is the process of teaching a model using data (very expensive, done by AI labs). Deployment is making a trained model available for inference. When you use an AI API, you're paying for inference compute.

Example: GPT-4 cost hundreds of millions of dollars to train, but inference costs are fractions of a cent per request because they're amortized across millions of users.
fundamentals

Input Tokens / Prompt Tokens

All tokens sent to the model in your API request: system prompt, conversation history, user message, document context, tool definitions, and any examples. Input tokens are counted and billed at the input rate. Strategies to reduce input tokens include shorter system prompts, context compression, and selective history trimming.

Example: A request with a 500-token system prompt, 2000-token document, and 100-token question has 2,600 input tokens before the model generates a single output token.
pricingfundamentals
K

KV Cache (Key-Value Cache)

An internal optimization where the model stores intermediate computations (key and value matrices) from previously processed tokens. When a prompt prefix is identical to a previous request, cached KV values can be reused, reducing latency and compute costs. Providers like OpenAI and Anthropic pass these savings on as "cache read" pricing.

Example: OpenAI automatically caches prompts longer than 1,024 tokens, and cached tokens are billed at $0.125/M (5× cheaper than standard input tokens).
performancecost optimization
L

Latency / TTFT / TPS

Latency is the total time from sending a request to receiving the complete response. TTFT (Time to First Token) is the delay before streaming begins — critical for perceived responsiveness. TPS (Tokens Per Second) is the generation speed. High-capacity models have lower TPS but higher quality; economy models can do 150–250 TPS.

Example: Gemini 1.5 Flash achieves ~250 TPS with low TTFT, making it excellent for customer-facing chatbots where speed matters. GPT-4o runs at ~80 TPS but with higher quality.
performance

LLM / SLM (Large/Small Language Model)

LLM refers to large neural networks trained on vast text corpora to generate and understand language — typically models with billions of parameters. SLM refers to smaller, more efficient models (1–10B parameters) optimized for speed and cost. SLMs trade some capability for dramatically reduced inference costs.

Example: GPT-4o is an LLM (~175B+ parameters); Llama 3.1 8B is an SLM that runs on consumer hardware yet beats older LLMs on many benchmarks.
fundamentals

LoRA (Low-Rank Adaptation)

A parameter-efficient fine-tuning method that adds small trainable weight matrices to a frozen base model. LoRA reduces fine-tuning compute and storage requirements by 10–100× versus full fine-tuning, making custom model adaptation practical for small teams. Popular for customizing open-weights models.

Example: A 70B-parameter Llama model would normally require terabytes of GPU memory to fine-tune; LoRA can adapt it using a fraction of that compute while achieving comparable results.
trainingcost optimization
M

Multimodal / Vision / Audio Transcription

Multimodal models can process multiple data types: text, images, audio, and video. Vision requests encode images as tokens (e.g., ~765 tokens for a 1024px image in GPT-4o). Audio transcription (Whisper) is typically billed per minute of audio. Multimodal requests cost more than text-only due to image tokenization overhead.

Example: Processing 100 product images with GPT-4o for description generation: ~765 tokens/image × 100 × $2.50/M = $0.19 just in image input costs.
featurespricing impact

Multi-Agent / Orchestration

A system where multiple AI agents collaborate, with one "orchestrator" agent directing specialized "worker" agents. Multi-agent pipelines multiply token costs: each agent call is a separate billable request. Cost planning for multi-agent systems must account for all agent interactions, not just final output.

Example: A research pipeline with 1 orchestrator + 3 specialist agents might make 10–20 LLM calls to answer one user question, costing 10–20× a single-agent approach.
architecturepricing impact
O

Open Weights / Open Source

Models where the trained weights are publicly released for download and use. "Open weights" means you can run the model yourself (e.g., Llama, Mistral). True open-source includes the training code and data too. Open-weights models can be self-hosted for privacy and cost control, or accessed via third-party inference APIs at competitive rates.

Example: Llama 3.1 70B is open-weights — downloadable for free and self-hostable, or available via Together AI at $0.59/M tokens with no proprietary lock-in.
fundamentalscost strategy
P

Prompt Engineering

The practice of crafting input prompts to elicit desired model behaviors. Effective prompt engineering can improve output quality without increasing cost, and sometimes reduces token usage by being more concise. Techniques include: chain-of-thought, few-shot examples, role assignment, output format specification, and constraint specification.

Example: Adding "Respond in exactly one sentence" to a prompt can reduce output tokens from 200 to 15 tokens while still getting the needed information.
promptingcost optimization
R

RAG (Retrieval-Augmented Generation)

A technique that combines vector search with text generation. Documents are embedded and stored in a vector database. At query time, relevant chunks are retrieved and inserted into the prompt as context. RAG improves accuracy and reduces hallucination but increases input token costs with every query.

Example: A customer support RAG system embeds 1,000 help articles. Each user question retrieves the 3 most relevant chunks (~1,500 tokens), adding $0.00375 to the input cost of each GPT-4o query.
architecturepricing impact

Rate Limiting / Throttling

Restrictions on API usage frequency to prevent abuse and ensure fair access. Providers set limits by: requests per minute (RPM), tokens per minute (TPM), and tokens per day (TPD). Hitting rate limits returns 429 errors. Higher rate limits are available at higher usage tiers or through paid commitments.

Example: OpenAI's free tier allows 3 RPM and 40,000 TPM for GPT-4o. A paid Tier 2 account gets 5,000 RPM and 2,000,000 TPM.
limitsapi
S

Streaming

A mode where the model sends output tokens incrementally as they're generated rather than waiting for the complete response. Streaming significantly improves perceived responsiveness for user-facing apps but does not reduce cost — you still pay for all output tokens. Some providers have slightly different rate limits for streaming vs non-streaming.

Example: ChatGPT-style interfaces use streaming so users see words appearing in real-time instead of waiting 5–30 seconds for the full response to appear.
apiperformance

System Prompt

Instructions sent to the model before the conversation that define its role, behavior, and constraints. System prompts are paid for as input tokens with every single request. A 1,000-token system prompt at GPT-4o rates ($2.50/M) costs $0.0025 per request — $2.50 per thousand requests, $75 per 30K requests/day.

Example: A customer service bot system prompt saying "You are a helpful assistant for Acme Corp. Only answer questions about our products..." gets re-sent (and re-charged) with every message.
pricingprompting
T

Temperature / Top-p

Sampling parameters controlling output randomness. Temperature (0–2) controls how "creative" vs deterministic the model is. Temperature 0 produces near-deterministic outputs (same input = same output), useful for consistent applications. Top-p (nucleus sampling) controls the probability mass considered at each step. Neither parameter affects token cost.

Example: Temperature 0 for code generation ensures consistent outputs. Temperature 0.9 for creative writing produces varied, surprising responses.
parameters

Throughput

The rate at which a system processes requests or tokens, measured in requests per second (RPS) or tokens per second (TPS). Higher throughput means more work done per unit time, which is important for batch processing and high-volume applications. Throughput is limited by rate limits, model speed, and your own infrastructure.

Example: A model generating 100 TPS that's handling 3 concurrent requests effectively produces 33 TPS per request — important to consider for user-facing applications.
performance

Token / Tokenization / Tokenizer

A token is the fundamental unit of text used by language models — roughly 4 characters or 0.75 words of English text. Tokenization is the process of splitting text into tokens. A tokenizer is the algorithm (e.g., tiktoken for OpenAI) that performs this splitting. All AI API pricing is based on tokens, making tokenization knowledge essential for cost estimation.

Example: "Hello, world!" tokenizes to ["Hello", ",", " world", "!"] = 4 tokens. "AI tokenization is fascinating" = 6 tokens. 1,000-word document ≈ 1,333 tokens.
fundamentalspricing
V

Vector Database

A database optimized for storing and searching embedding vectors using approximate nearest-neighbor algorithms. Used in RAG systems to find relevant documents given a query embedding. Examples: Pinecone, Weaviate, Chroma, pgvector. Vector search costs are typically much lower than LLM inference costs.

Example: Searching 1 million document embeddings in Pinecone to find the 5 most relevant results costs fractions of a cent per query — much cheaper than the LLM call that follows.
raginfrastructure
Z

Zero-Shot Learning

Asking a model to perform a task without providing any examples in the prompt. Zero-shot prompting uses the fewest input tokens but may produce lower quality results on specialized tasks. The cost savings vs few-shot depend on whether the quality difference is acceptable for your use case.

Example: "Classify this review as positive or negative: 'Great product!'" is zero-shot. Adding 3 labeled examples would be few-shot, using more tokens but potentially improving accuracy.
